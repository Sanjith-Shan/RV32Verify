# Functional coverage

Reproduce: `./regress coverage -n 250 -j 2` (riscv-tests in both wait-state
profiles plus random seeds 1 to 250; about 15 minutes on the machine in
[RESULTS.md](RESULTS.md)). The report below is generated by
`scripts/cov_report.py` from the per-run Verilator coverage databases. Every
item maps to a feature in [VERIFICATION_PLAN.md](VERIFICATION_PLAN.md).

## Result, stated first

**98.2% of bins (1288 / 1311).** Every pipeline, dependency, branch,
load/store, x0 and trap item is at 100%. The 23 bins still open are all in
the operand-value crosses of the ALU groups, listed below with the reason.

## Remaining holes and why

All 23 open bins are a specific pair of boundary values on the two operands
of one instruction, for example `ADD` with rs1 = INT_MIN and rs2 = INT_MAX,
or `XORI` with rs1 = INT_MIN and immediate 0. To hit one, both source
registers must hold one exact value each at the moment the instruction
reads them. The generator seeds boundary values into registers and biases
sources towards recently written registers, which closed 196 of the 219
operand-cross bins that were open in the first report, but the last pairs are each
roughly a one-in-several-thousand event per instruction.

These are not closed, on purpose, for now. What they would add is checking
the ALU datapath on two more value combinations, which the reference-model
compare already does for every value combination that occurs. The way to
close them is a directed sequence (load the two values, run every ALU op)
or a generator mode that pairs boundary seeds; that is listed as follow-up
work, not done.

## How closure went

The numbers below are intermediate states during development. They came
from the same commands, run on code that was not committed at the time, so
only the final row is reproducible from this repository.

| Step | Seeds | Coverage | What changed before the next step |
|---|---:|---:|---|
| first merged report | 40 | 82.8% (1086/1311) | found coverage-model bug 1 (`cp_stall_then_forward`, see [BUGS_FOUND.md](BUGS_FOUND.md)); added a boundary-value seeding instruction (`w_seed`); added wrong-path instructions after the final trap (trap must beat a younger load-use stall); JALR setup with up to 4 fillers (dependency distance 4 and 5+); per-seed knob profiles in the regression |
| second | 100 | 94.5% (1239/1311) | found coverage-model bug 2 (`cp_trap` guard hid cause 0); the shadow instructions had displaced the `j .` that used to give "trap beats a younger redirect", so the shadow now starts with a taken branch half the time; `alu_corner` profile ties sources to recent destinations more often |
| final | 250 | **98.2% (1288/1311)** | (this report) |

SVA cover properties are reported with the covergroups. They are an
independent count of the same pipeline events and are how bug 1 was found.
